# ۱۳. امنیت دفاعی در Bash

منابع امنیتی ارائه‌شده روی **اعتبارسنجی ورودی، حداقل دسترسی، مجوز مناسب، احتیاط با sudo و تحلیل Logها** تأکید دارند.

## Command injection

به‌جای ساخت رشته فرمان:

```bash
# مناسب‌تر: داده به‌صورت یک آرگومان باقی می‌ماند
grep -F -- "$needle" "$logfile"
```

ورودی را validate کنید و در صورت محدود بودن دامنه، allowlist بسازید.

## مجوز و umask

```bash
umask 027
install -m 640 /dev/null report.log
```

## PATH

در اسکریپت privileged به PATH غیرقابل اعتماد تکیه نکنید. محیط اجرا را محدود و قابل پیش‌بینی کنید.

## Logهای احراز هویت

```bash
journalctl -u ssh --since "today" | grep -i "failed"
```

این مثال برای **تحلیل دفاعی Log سیستم تحت مدیریت شما** است.

## داده حساس

Password، Token، کلید خصوصی یا Cookie را در history، argument list یا Log قرار ندهید.

## عملیات حساس

برای تغییرات گسترده فایل‌ها، ابتدا Scope را محدود کنید، خروجی انتخاب را بررسی کنید و Backup/rollback داشته باشید. اجرای Shell با سطح دسترسی بالا باید حداقل و قابل حسابرسی باشد.
